# Установка через GitDeck

В панели выберите **Добавить модуль → Vano Remote — удалённый доступ**. Параметры общего репозитория, папка `vano_remote`, каталог `/opt/vano-remote` и сервис `web` заполнятся автоматически. Сохраните и нажмите **Обновить из Git**. Первая установка разрешена только в пустой каталог.

Затем в **Настройки сайта** выберите HTTPS-прокси марафона/Пульса и `APP_URL=https://connect.vano.sbena.net/`, сохраните настройки. DNS поддомена должен указывать на сервер. В клиентах Windows и Android используйте `wss://connect.vano.sbena.net`.

Для установки из панели используется `ops/compose.yaml`, который копируется в серверный `compose.yaml` один раз. Повторные обновления сохраняют Compose, `.env`, HTTPS-наложение и постоянный том. Панель делает резервную копию базы регистрации устройств перед обновлением. Вручную не смешивайте команды отдельного проекта ниже (сервис `relay`) с экземпляром GitDeck (сервис `web`).

Существующая установка RustDesk независима. EXE и APK следует собирать из `windows/` и `android/`; биометрия и захват экрана требуют проверки на реальном телефоне.

# Vano Remote 0.1 — тестовая версия

Собственное приложение для личного доступа Windows ↔ Android через сервер на Hetzner.
Это отдельный проект: с сервером RustDesk несовместим, установленный RustDesk не заменяет.

## Что реализовано

- Android → Windows: просмотр первого монитора, левый/правый клик, перетаскивание, прокрутка, отправка текста, Enter/Backspace/Esc.
- Windows → Android: просмотр экрана после системного подтверждения, нажатия и свайпы, «Назад», «Домой», список приложений, ввод текста в активное поле.
- Каждое подключение Android открывает ключ через сильную биометрию Android Keystore. На Redmi ориентируемся на отпечаток. Лицо допустимо только если Android относит его к сильной биометрии.
- Передача экрана Android сопровождается постоянным уведомлением с кнопкой остановки. Удалённые команды телефону принимаются только во время этой передачи.
- В Windows доступ включается явно и прекращается при закрытии программы. Кнопка «Отозвать телефон» меняет секрет привязки и отключает старый телефон.
- WebSocket-соединение только через TLS (`wss://`). Экран и команды дополнительно шифруются между устройствами AES-256-GCM; relay не получает секрет привязки. Свежие случайные значения при установке сессии и счётчики сообщений защищают от повтора команд из старой сессии.

## Что пока ограничено

- Это первая тестовая версия, не замена проверенному продукту для критичного доступа. Независимого аудита криптографии и приложения не было. Протокол с общим секретом не обеспечивает forward secrecy при последующей утечке секрета.
- Расширение рабочего стола на телефон **не реализовано**. Просмотр первого экрана есть; настоящий второй монитор потребует виртуального драйвера дисплея Windows.
- Нет передачи файлов, звука, аппаратного видеокодирования, фоновой службы Windows и автоматического запуска. Компьютер должен быть включён, не спать, приложение открыто, доступ включён. Экран входа Windows и защищённый рабочий стол UAC не поддерживаются.
- Нет полного проброса физической клавиатуры и всех сочетаний клавиш. Передача текста на Android заменяет содержимое активного редактируемого поля.
- Используются JPEG-кадры примерно 3–5 раз в секунду, а не видеопоток. Возможны задержки и заметный расход трафика.
- Android 11+, без root. Защищённые окна и некоторые системные экраны Android не захватываются. После остановки или перезагрузки требуется новое разрешение трансляции. При повороте телефона остановите и снова включите трансляцию.
- Когда Android-клиент уходит в фон без включённой передачи собственного экрана, сеанс закрывается. Повторный вход — снова через отпечаток. Обрыв сети также требует повторного входа.
- В первой версии один Windows-компьютер и один Android-телефон в одной привязке.

## 1. Сервер Docker

Для своего приложения используем новый адрес **connect.vano.sbena.net**. Уже работающий RustDesk на `remote.vano.sbena.net` можно оставить.

1. DNS-запись `A connect.vano.sbena.net` должна указывать на текущий IP Hetzner. Если используется Cloudflare, сначала выберите DNS only.
2. Скопируйте исходный проект в новую папку сервера, например `/opt/vano-remote`. Нужны `compose.yaml`, `server/` и, если HTTPS-прокси в Docker, `compose.proxy.yaml`.
3. Запустите из этой папки:

```bash
docker compose -p vano-remote up -d --build
curl http://127.0.0.1:21120/health
```

Ожидается JSON с `service: Vano Remote`. Порт 21120 слушает только localhost; наружу открывать его не требуется.

### HTTPS рядом с существующими сайтами

Не запускайте второй прокси на портах 80/443 и не заменяйте конфигурацию существующего сайта. Добавьте отдельный домен в уже работающий HTTPS-прокси.

Если используется **Caddy внутри Docker**, сначала определите его сеть:

```bash
docker inspect glava-marathon-proxy-1 --format '{{json .NetworkSettings.Networks}}'
docker inspect glava-marathon-proxy-1 --format '{{json .Mounts}}'
```

В папке проекта создайте `.env` с реальным именем существующей сети:

```text
PROXY_NETWORK=имя_сети_прокси
```

Затем:

```bash
docker compose -p vano-remote -f compose.yaml -f compose.proxy.yaml up -d --build
```

Добавьте в существующий Caddyfile отдельный блок из `Caddyfile.example`:

```caddy
connect.vano.sbena.net {
    reverse_proxy vano-remote-relay:8080
}
```

Перезагрузите Caddy его обычным способом, после проверки конфигурации. Конкретную команду выбирайте по реальному пути Caddyfile и способу запуска прокси. Не копируйте пример поверх текущего файла.

Если **Caddy установлен на самом Ubuntu**, достаточно основного `compose.yaml`, а upstream в блоке домена должен быть `127.0.0.1:21120`.

Проверка с компьютера:

```text
https://connect.vano.sbena.net/health
```

Ответ должен быть JSON нашего relay, с действительным HTTPS-сертификатом. Доступ приложения проходит через стандартный 443; прокси должен поддерживать WebSocket Upgrade (Caddy делает это автоматически).

### Остановка и обновление

Используйте те же compose-файлы, с которыми запускали сервис. Например для Docker-прокси:

```bash
docker compose -p vano-remote -f compose.yaml -f compose.proxy.yaml stop
docker compose -p vano-remote -f compose.yaml -f compose.proxy.yaml up -d --build
```

База регистрации находится в именованном томе `vano-remote_relay-data`. Сервер не знает секрет шифрования. Не публикуйте базу и не включайте логирование заголовка Authorization в прокси.

## 2. Windows

1. Запустите `VanoRemote.exe`. Файл тестовый, без подписи издателя; Python отдельно не нужен.
2. Оставьте адрес `wss://connect.vano.sbena.net`, когда сервер и HTTPS уже настроены.
3. Нажмите «Код привязки». Перенесите JSON-код на свой телефон безопасным способом. **Этот код — секрет доступа**, не присылайте его в чат и не добавляйте в Git.
4. Нажмите «Включить доступ». Окно должно оставаться открытым. Пока компьютер не привязан к relay этим запуском, Android не сможет зарегистрироваться.

Настройки Windows сохраняются в `%LOCALAPPDATA%\VanoRemote\pairing.json`, доступ к файлу ограничивается текущим пользователем и SYSTEM. Не передавайте этот файл. Пользователь с административным доступом к Windows потенциально может получить его содержимое.

## 3. Android / Redmi

1. Установите `VanoRemote-0.1-debug.apk`. Это APK тестовой сборки, Android 11+.
2. Предварительно настройте отпечаток в системных настройках Redmi.
3. Вставьте код из Windows в приложение, нажмите «Привязать» и подтвердите отпечатком. Код сохранится в зашифрованном виде, а поле очистится.
4. Нажмите «Войти • отпечаток», подтвердите и дождитесь экрана Windows. На ПК уже должен быть включён доступ.
5. Касание экрана — клик. Провести пальцем — перетаскивание. Для правого клика сначала нажмите кнопку «Правый клик», затем коснитесь нужной точки. Кнопки «ПК ↑/↓» прокручивают окно под курсором.

Для управления **телефоном с компьютера**:

1. В Android-клиенте нажмите «Разрешить управление» и вручную включите службу «Vano Remote — управление» в специальных возможностях. Android/HyperOS может потребовать разрешить ограниченные настройки для установленного из APK приложения.
2. Вернитесь в приложение и снова войдите по отпечатку, если соединение закрылось при переходе в настройки.
3. Нажмите «Передать экран» и подтвердите системный запрос на весь экран. После этого экран телефона появится в Windows-приложении.
4. Переключитесь на другое приложение на телефоне: окно Vano Remote само защищено от захвата, поэтому в нём может отображаться чёрный экран.
5. Нажатия и протягивания мышью в Windows управляют телефоном. «Передать экран» повторно или «Остановить» в уведомлении отключает трансляцию и управление.

Если отпечаток в системе изменён или ключ Android Keystore недоступен, удалите привязку в приложении и создайте её заново. Для отзыва доступа потерянного телефона обязательно нажмите **«Отозвать телефон» в Windows**.

## Сборка из исходников

Android: полный JDK 17+, Android SDK Platform 34, Gradle 8.14:

```text
cd android
gradle :app:assembleDebug
```

Windows: Python 3.12–3.14, из корня проекта:

```text
python -m venv .venv
.venv\Scripts\python -m pip install -r windows\requirements.txt pyinstaller
.venv\Scripts\python windows\app.py
.venv\Scripts\python -m PyInstaller --onefile --windowed --name VanoRemote --paths . --hidden-import pynput.keyboard._win32 --hidden-import pynput.mouse._win32 windows\app.py
```

Проверки протокола и relay:

```text
python -m unittest discover -s tests -v
```

Исходники и конфигурацию можно положить в `my_project/gitdesk`, когда известен точный путь к этой папке. Файлы привязки и серверные данные в Git не включаются.
