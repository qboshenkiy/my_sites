# Telegram Mini App и Android

У сайта, Mini App и Android одна база, планы, круги и роли. Аккаунты не дублируются.
В Telegram автоматически открывается аккаунт с подтверждённой привязкой Telegram.
Android использует существующий вход через бота либо логин команды.

## Сначала подключите HTTPS через GitDeck

Текущий адрес `http://vano.sbena.net:8081/` подходит для браузера, но Telegram
Mini App требует HTTPS **самой страницы**, а не только API.
Целевой адрес для текущего сервера: `https://vano.sbena.net/`.

1. Обновите **Марафон чтения** в GitDeck, включая сервис `bot`.
2. Убедитесь, что DNS `vano.sbena.net` указывает на этот сервер, а в Hetzner
   доступны входящие TCP 80 и 443. Если на этих портах уже есть прокси другого
   проекта, добавьте маршрут марафона в него: второй прокси на тех же портах
   не запустится. Приложения на 8080/8083 не занимают эти порты.
3. В **Настройках модуля** марафона выберите `compose.https.yaml`;
   сервисы оставьте `web, bot`, профиль — `telegram`. Сохраните.
4. В **Домен и Telegram** задайте `DOMAIN=vano.sbena.net` и
   `APP_URL=https://vano.sbena.net`. Сохраните **с применением настроек**.
   При применении GitDeck сам поднимает `proxy` из HTTPS-конфигурации;
   добавлять `proxy` в поле сервисов не нужно.
5. Откройте `https://vano.sbena.net/` и убедитесь, что браузер принимает
   сертификат. Адрес марафона после перехода — без `:8081`.

Используется уже включённая в проект HTTPS-конфигурация и Caddy. Новый сервер
не нужен. Том `marathon_data` сохраняется благодаря прежнему имени Compose-проекта
`glava-marathon`; не выполняйте `docker compose down -v`.
Если серверная копия `compose.https.yaml` или `deploy/Caddyfile` была изменена,
сначала сравните её с репозиторием: GitDeck специально сохраняет такие файлы.

## Открытие Mini App

После HTTPS перезапустите/обновите бота и отправьте ему `/start`.
В меню бота появится кнопка **Марафон**. Дополнительно работают
**📱 Марафон** в клавиатуре и `/app`: бот пришлёт кнопку **Открыть марафон**.
Подтверждение привязки аккаунта тоже заканчивается кнопкой приложения.

Адрес страницы: `https://vano.sbena.net/index.php?miniapp=1`.
Открывайте её кнопкой `web_app` из бота: обычная ссылка в браузере не содержит
подписанных данных Telegram. Для обычного браузера остаётся прежний вход.

На старте worker вызывает `setChatMenuButton`. Если Telegram временно не принял
настройку меню, текстовая команда `/app` и inline-кнопка продолжают работать.
BotFather для этих двух способов запуска дополнительно настраивать не требуется.
Для отдельной кнопки в профиле бота можно позже настроить **Main Mini App** в BotFather.

Параметры берутся из существующих `APP_URL`, `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_BOT_USERNAME`. Дополнительного токена приложения нет.
В настройках сайта видна сформированная ссылка Mini App. Наличие ссылки означает
настройку HTTPS-адреса, а не проверку сертификата сервера.

## Вход и права

Сервер проверяет HMAC-SHA256 исходной `initData`, время выдачи (не более часа,
до 30 секунд отклонения часов вперёд), структуру и уникальность параметров.
`initDataUnsafe`, имя и присланная роль не используются для авторизации.
Права читаются из базы при каждом запросе. Отключённые, удалённые и непривязанные
аккаунты не допускаются. Mini App не создаёт пользователя или администратора.
При смене аккаунта Telegram прежняя веб-сессия заменяется проверенным аккаунтом.

Наш код отправляет данные входа только в POST-запросе с CSRF, не переносит их
в URL API, localStorage или журнал. Cookie — HttpOnly; на HTTPS в Mini App используется
Secure/SameSite=None для встраивания, у обычного сайта сохраняется SameSite=Lax.
Ограничения сторонних cookie конкретного браузера могут потребовать открытия
приложения в мобильном клиенте Telegram.
История входов и изменений из Mini App помечается в существующем журнале.

## Android

Исходники: `native/android/`. Это нативная Android-оболочка с WebView,
которая использует уже сделанный интерфейс марафона и общий сервер.
Есть сохранение сессии, системная кнопка/жест «Назад», безопасные области экрана,
открытие Telegram с возвращением к подтверждению входа, экран ошибки/повторного
подключения и сохранение отчётов через системный выбор файла.
Нужен интернет и HTTPS. Отдельной базы на телефоне и режима офлайн нет.

Тестовый APK можно установить вручную. Для обновлений приложений через магазин
в дальнейшем нужна отдельная release-подпись; debug APK предназначен для проверки.
Изменения интерфейса и планов загружаются с сайта и не требуют пересборки APK.
Изменение домена или нативных функций требует новой сборки.

Чтобы собрать APK без командной строки: в репозитории GitHub откройте
**Actions → Build Marathon Android APK → Run workflow**, укажите HTTPS-адрес
марафона. После успешной проверки скачайте архив `glava-marathon-android-debug`
из **Artifacts** задания. Распакуйте и передайте APK на Android.
Первый запуск workflow может потребовать включения GitHub Actions в репозитории.
Ключ подписи тестовой сборки GitHub может отличаться от локального: такие сборки
устанавливаются после удаления предыдущей тестовой версии.

## Проверки

`python tests/miniapp.py` — настоящие HTTP-запросы, независимые подписанные
фикстуры Telegram, CSRF, подделки/сроки/дубликаты, роли, отключение аккаунта,
запись чтения, отсутствие токенов и initData в журнале.
`MINIAPP_UI=1 python tests/miniapp.py` добавляет Playwright/Chromium:
вход, телефон, safe area, Telegram BackButton и подтверждение плана.
Настоящие Telegram-клиент и сертификат сервера проверяются после HTTPS-развёртывания.

Официальные протоколы:
[Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app),
[WebAppInfo](https://core.telegram.org/bots/api#webappinfo),
[Android WebView](https://developer.android.com/develop/ui/views/layout/webapps/webview).
