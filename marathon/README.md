# Глава — марафон чтения

Второй независимый сайт: **22 недели, 12.10.2026–14.03.2027 включительно**, часовой пояс Asia/Bishkek. Основной учёт — главы и дни чтения. Участники отмечают чтение на сайте или пишут боту «прочитал 50»; команда ведёт недельную ведомость. Бот также привязывает Telegram и подтверждает вход.

В план недели можно добавить книги с диапазонами глав; цель считается автоматически. На телефоне основной сценарий — «План прочитан» → количество дней → подтверждение. Есть сравнение фактического и планового темпа, статусы просрочки и позднего выполнения. Поздняя отметка полного плана разрешена без открытия недели; редактирование старых записей требует открытия администратором. Excel содержит недельную ведомость, сводку и план книг за 22 недели. Подробнее — в [UPDATE.md](UPDATE.md).

Для существующего сервера используйте `dist/reading-marathon-update.tar.gz` и [UPDATE.md](UPDATE.md), сохраняя токен, базу, домены и compose-файлы. Старые страницы и минуты остаются в истории.

## Роли

- **Участник:** вход через привязанный Telegram, свои главы, дни, дневной темп и график за 22 недели. Может добавлять и удалять собственные ежедневные отметки в открытых неделях. Чужие данные недоступны.
- **Модератор:** все участники и отчёты, добавление участников, приглашения Telegram, ввод и исправление результатов открытых недель, журнал изменений, Excel-ведомость.
- **Администратор:** права модератора, создание сотрудников, изменение ролей существующих пользователей, планы глав для каждой недели и открытие прошедших недель для исправлений. Последнего администратора отключить нельзя.

По умолчанию план — 7 глав на неделю; задайте фактические значения для каждой из 22 недель в настройках. Таблица сортируется по прочитанным главам. Итог не может превышать недельный план. Будущие и завершённые недели закрыты для ввода; администратор может открыть прошедшую неделю. Дни считаются по уникальным датам отметок, с возможностью ручного значения в недельном итоге.

## Быстрый запуск на Hetzner

При создании сервера выберите **Apps → Docker CE**. [Инструкция Hetzner](https://docs.hetzner.com/cloud/apps/list/docker-ce/).

Загрузите `dist/reading-marathon.tar.gz` по SFTP или SCP. На сервере:

```bash
mkdir -p /opt/marathon
tar -xzf reading-marathon.tar.gz -C /opt/marathon
cd /opt/marathon
cp .env.example .env
nano .env
bash start.sh
```

Для HTTP укажите `APP_URL=http://IP_СЕРВЕРА:8081`. Разрешите TCP 8081 в Hetzner Firewall. Откройте сайт, создайте логин и пароль первого администратора. PHP, SQLite и таблицы настраиваются автоматически. На этом этапе можно создавать участников и вносить результаты, даже если бот ещё не настроен.

## Новый Telegram-бот

1. Откройте в Telegram [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username бота.
2. Запишите токен и username **без @** в `.env` на сервере:

```dotenv
TELEGRAM_BOT_TOKEN=ТОКЕН_ИЗ_BOTFATHER
TELEGRAM_BOT_USERNAME=your_marathon_bot
APP_URL=https://read.example.com
```

3. Запустите сайт с worker бота:

```bash
bash start.sh http telegram
```

Для HTTPS или общего proxy используйте соответствующий режим, описанный ниже. Проверка бота:

```bash
docker compose --profile telegram logs --tail=50 bot
```

Для другого режима добавьте `-f compose.https.yaml` или `-f compose.shared.yaml`. Токен не хранится в браузере или архиве. `.env` хранится только на сервере; задайте `chmod 600 .env`. Worker получает сообщения через long polling, отдельный webhook и домен для самого бота не нужны. Не запускайте другие обработчики для этого же бота. [Telegram: getUpdates](https://core.telegram.org/bots/api#getupdates), [привязка через deep links](https://core.telegram.org/bots/features#deep-linking).

## Как участник привязывается и входит

1. Админ/модератор добавляет участника на сайте и нажимает «Пригласить».
2. Передаёт **персональную** ссылку соответствующему участнику. Ссылка одноразовая, действует 24 часа; создание новой отменяет предыдущую.
3. Участник открывает бот, нажимает Start и подтверждает привязку к указанному имени.
4. На сайте нажимает «Войти через Telegram», открывает бот и подтверждает вход. Кабинет открывается в исходной вкладке автоматически.

Вход привязан к браузерной сессии, действует 5 минут и используется один раз. Telegram ID проверяется по сообщениям Telegram API. Сотрудник может привязать свой Telegram в «Мой аккаунт» и входить через него; логин/пароль остаются запасным способом входа. Участники не регистрируются произвольно: для них создаётся аккаунт командой марафона.

## HTTPS на отдельном сервере

Укажите `DOMAIN=read.example.com` в `.env` и создайте DNS A-запись на IP сервера. Разрешите TCP 80/443. Если имеется AAAA-запись, IPv6 тоже должен вести на этот сервер.

```bash
docker compose down
bash start.sh https telegram
```

Caddy получает и обновляет сертификат. В HTTPS-режиме `APP_URL` устанавливается из DOMAIN. [Автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https).

## Оба сайта на одном сервере: «Пульс» и «Глава»

Для проверки можно держать «Пульс» на порту 80, а «Главу» — на 8081. Для двух доменов используйте **один** Caddy из «Пульса», чтобы они не занимали одни и те же порты 80/443.

1. Запустите «Пульс» в HTTPS-режиме по его инструкции; это создаст сеть `pulse_default` и общий proxy.
2. В `.env` марафона укажите `DOMAIN=read.example.com` и параметры нового бота. Настройте DNS поддомена.
3. Если марафон ранее запущен отдельно, остановите его соответствующим compose-файлом без `-v`, затем:

```bash
cd /opt/marathon
bash start.sh shared telegram
```

4. Добавьте в `/opt/pulse/deploy/Caddyfile` ещё один блок, сохраняя существующий:

```caddy
read.example.com {
    encode gzip zstd
    reverse_proxy marathon:80
}
```

5. Примените конфигурацию proxy:

```bash
cd /opt/pulse
docker compose -f compose.https.yaml exec proxy caddy reload --config /etc/caddy/Caddyfile
```

Каждый сайт имеет независимую базу и администратора. Для команд управления «Главой» в этом режиме используйте `docker compose -f compose.shared.yaml --profile telegram ...`.

## Данные, обновления и копии

База сохраняется в Docker volume `glava-marathon_marathon_data`, вне веб-каталога. Остановка, обновление образа и перезагрузка сервера не удаляют данные. **Не используйте `down -v`** для рабочего проекта.

Обновление: загрузите новые файлы без `.env` и запустите выбранную команду `bash start.sh ...` ещё раз. Контейнеры запускаются после перезагрузки, если включена служба Docker.

Резервная копия работающей базы:

```bash
docker compose exec -T web php /opt/marathon/backup.php /var/lib/marathon/backup.sqlite
docker compose cp web:/var/lib/marathon/backup.sqlite ./backup.sqlite
docker compose exec -T web rm /var/lib/marathon/backup.sqlite
```

Для HTTPS/shared используйте соответствующий `-f`. Скачайте копию по SFTP и храните отдельно от сервера. Перед восстановлением остановите и web, и bot, сохраните текущую копию; замените базу и удалите старые WAL/SHM-файлы перед запуском. Не восстанавливайте поверх работающей SQLite.

## Локальная разработка

PHP 8.1+ с `pdo_sqlite`, `mbstring`, `curl` (curl нужен worker бота):

```powershell
& 'C:/laragon/bin/php/php-8.3.33-Win32-vs16-x64/php.exe' -S 127.0.0.1:8091 router.php
```

Или `docker compose up -d --build` из папки марафона. В локальном `.env` задан порт 8091.

Быстрый локальный запуск из PowerShell: `./start-local.ps1`. Если Docker Desktop остановлен, скрипт запускает его и затем поднимает сайт. Если после перезагрузки сайт не открывается, сначала запустите Docker Desktop.

Проверка:

```powershell
python tests/e2e.py
```

Тест использует временную SQLite и имитирует входящие сообщения Telegram, не отправляя ничего настоящему боту. Проверяет даты, роли, отчёты, привязку, подтверждение входа, одноразовость, изоляцию браузеров и приватность участников.

Архивы: `python tools/package.py`. Пароли, база и bot token не попадают в архив.

Ограничение: проверка реального Telegram требует вашего нового бота и действительного токена. Без них проверяется протокол авторизации на имитации Telegram updates. Статус «конфигурация добавлена» на сайте означает наличие параметров, работу worker проверяют его логи. Шрифты загружаются с Google Fonts; без интернета используется системный шрифт.


## Подробный журнал чтения и просмотр в Telegram

Для новых изменений сохраняются автор и участник (имена на момент действия), дата и время,
источник (сайт / Telegram), неделя, круг и значения до/после: главы, дни, ручной расчёт дней,
статус выполнения, дата завершения, книги и комментарий. Записываются добавление и удаление
отметок, исправление и сброс итога, завершение плана, начало/удаление/восстановление круга,
изменения недельного плана и аккаунтов. Идентификатор операции связывает события одного запроса.
Пароли, их хеши, токены, cookie и полные запросы в журнал не записываются.

На сайте откройте **Журнал изменений**: выберите участника и неделю, раскройте «Подробности».
Страницы «Ранее / Новее» позволяют просмотреть историю за пределами последних 100 событий.
Время отображается в часовом поясе марафона (по умолчанию Asia/Bishkek).

В личном чате с ботом администратору доступны **🧾 Журнал** и `/logs`.
Нажмите «Подробнее» для полей «Было → стало». Есть выбор недели, свежие и предыдущие события.
Для истории конкретного участника: **👥 Выбрать участника → карточка → 🧾 История участника**.
Просмотр журнала отменяет незавершённый ввод результата: при необходимости начните его заново.
Участники, модераторы и групповые чаты не получают доступ к журналу через бота;
на сайте доступ команды к журналу сохраняется.

Обновите марафон **вместе с сервисом bot** через GitDeck, затем отправьте `/start` боту,
чтобы обновилась клавиатура. База обновляется автоматически без очистки. Прежние записи
сохраняются в общем журнале; прежние значения и фильтр недели для старых записей задним
числом не восстанавливаются. Новые подробности записываются после установки обновления.

Проверка без настоящего Telegram: `python tests/audit_bot.py`.
Для проверки страницы браузером: `AUDIT_UI=1 python tests/audit_bot.py` (Playwright/Chromium).


## Telegram Mini App и Android

Добавлено открытие марафона внутри Telegram: кнопка «Марафон» в меню бота,
`/app` и кнопка запуска после привязки. Вход выполняется по проверенной подписи
Telegram в уже привязанный активный аккаунт, с прежними ролями и результатами.
В приложении поддерживаются безопасные области экрана и кнопка «Назад» Telegram.
Обычный сайт и подтверждение входа через бота продолжают работать.

Mini App требует HTTPS сайта. При текущем HTTP бот предлагает обычную ссылку.
Подробная настройка существующего сервера через GitDeck, без потери базы:
[MINIAPP.md](MINIAPP.md). Для `vano.sbena.net` подготовлен переход на
`https://vano.sbena.net/` через существующий `compose.https.yaml`.
Включение TLS на сервере выполняется отдельно от обновления кода.

Android-проект находится в `native/android`, сборка запускается из GitHub Actions
**Build Marathon Android APK** с указанием HTTPS-адреса сайта. Это оболочка текущего
интерфейса с общей серверной базой, постоянной сессией, кнопкой «Назад» и сохранением
отчётов. Тестовый APK не заменяет release-подпись и публикацию в магазине.
Обновите марафон вместе с ботом, после HTTPS отправьте боту `/start` или `/app`.


## Аккаунты для Пульса

GitDeck 1.5.0 позволяет подключить Пульс к существующему списку участников: обновите
оба сайта, затем на карточке Пульса выберите «Подключить марафон». В Пульс передаются
имя, стабильный идентификатор, роль и активность аккаунта, без паролей, Telegram ID
и результатов чтения. Участник подтверждает свой профиль на сайте марафона.
Вход защищён одноразовым кодом, привязкой к исходному браузеру, сроком 90 секунд
и проверкой активного аккаунта. Подробнее — в README Пульса в корне репозитория.

После подключения администратор может прямо из марафона нажать
**Передать участников в Пульс**. Повторный экспорт обновляет аккаунты без дублей.
Участники могут входить в Пульс через его отдельного нового Telegram-бота,
используя Telegram, уже привязанный здесь. Бот и токен марафона не меняются.
Новый бот Пульса настраивается и запускается через GitDeck 1.5.1.

### Ежедневный ориентир в Telegram

Работающий сервис `bot` ежедневно после 08:00 (`MARATHON_TIMEZONE`, по умолчанию Asia/Bishkek) отправляет активным участникам с привязанным Telegram цель к концу дня: отдельно для темпа на 7 и на 6 дней. Используются книги, диапазоны глав и начало недели из действующего личного календаря; недельные повторы не сдвигают даты. Цель накопительная: округление вверх до целой главы, последняя цель — последняя глава последней книги. В седьмой день шестидневного плана повторяется финальная глава и поясняется, что это запасной день. Если книги не заданы, отправляется количество глав.

Получение отметок чтения не меняется. Успешная отправка сохраняется в SQLite, перезапуск работника её не повторяет. При сбое повтор через 5 минут; после простоя отправляется только ориентир текущего дня. Как и у обычной доставки Telegram, потеря ответа после принятой отправки может привести к повтору. До старта и после окончания марафона сообщений нет. Обновлять нужно web и bot вместе через GitDeck.

### «Как догнать?» и ручной отчёт в группу

Кнопка «🧭 Как догнать?» доступна в личном меню участника. Показывает долг до ориентира на конец текущего дня и варианты 10/15/20 глав в день: дату выхода на график и общее количество глав до этой даты. Прогноз включает следующие недели (темп на 7 дней), начинает чтение сегодня и не считает повторные круги новым долгом. Если вариант приводит к дате позже конца марафона, это явно подписано. Главы разной длины: это ориентир, а не гарантия нагрузки по времени. Неотмеченное чтение нужно сначала внести. Бот теперь распределяет подтверждённое чтение по всем пропущенным неделям от самой ранней к текущей.

Ручная групповая отправка:
1. Добавьте бота в группу и разрешите ему писать. Для канала этот механизм не используется.
2. С привязанного аккаунта администратора Marathon отправьте в группе `/reading_here`. В группе с темами команда запоминает также текущую тему.
3. В личном чате бота отправьте `/menu`, нажмите «📣 Отправить в группу».
4. Просмотрите отчёт (ориентир по общему календарю, число глав на день и персональные расчёты для отстающих участников), затем подтвердите отправку. Имена и расчёты будут видны группе.

Самостоятельная кнопка «Как догнать?» отвечает только запросившему участнику. Групповая отправка выполняется вручную, не ежедневно. Предпросмотр действует 10 минут; подтверждённые части отчёта сохраняются в SQLite и отправляются работником bot с повтором после сбоя. Смена группы, отзыв прав администратора или его сессии отменяет старую очередь. Отчёт — снимок расчёта на дату предпросмотра. Для свежих данных создайте новый.
