# Обновление марафона до учёта глав

Все роли (участник, модератор, администратор) остаются в ведомости, личном плане и Excel. Роль определяет только права. Администратор открывает «Аккаунт» в ведомости, команде или профиле: меняет имя, роль, логин, пароль и статус. «Удалить пользователя» переносит аккаунт в архив, закрывает вход и сохраняет историю. Кнопка «Архив пользователей» восстанавливает аккаунт с результатами. Старые сессии после восстановления остаются закрытыми; нужен новый вход. Свой аккаунт нельзя удалить, отключить или понизить.

## Книги, отметка всего плана и просрочка

В карточке открытой недели есть **«Внести свой результат» / «Изменить главы и дни»**. Участник редактирует свои главы, дни, название и комментарий; команда — результаты участников. Вводится общий итог, уже включающий Telegram и дневные отметки. Даже если итог ниже их суммы, сами дневные записи остаются в истории: сохраняется отдельная корректировка. Новые ежедневные главы прибавляются к исправленному итогу. В форме есть отдельный сброс всей недели с подтверждением: удаляются её дневные записи, главы, дни и выполнение, но не план книг и не архив страниц/минут. Закрытые недели нужно сначала открыть администратору; поздняя первая отметка полного плана разрешена, как описано ниже.

Ручная корректировка хранится в новом поле SQLite. При откате к старому коду без поддержки этого поля она остаётся в базе, но старый интерфейс её не применяет; используйте версию с поддержкой корректировок для просмотра правильного итога.

В «Настройки → План чтения → Книги и главы» можно указать несколько книг с диапазонами, например «Матфей 1–7» и «Марк 1–3». Недельный план автоматически станет 10 глав. Без списка книг продолжает работать прежний общий план в главах. Уже внесённые результаты и Telegram-привязки сохраняются; книги к старым планам автоматически не придумываются.

Участник нажимает **«План прочитан»**, указывает количество дней и подтверждает весь недельный объём. Ранее внесённые главы учитываются, повторное нажатие не удваивает результат. Фактический темп = главы недельного плана / дни чтения; плановый = главы / 7. Можно выбрать расчёт по ежедневным отметкам: берётся число различных дат, а если их нет — число прошедших дней недели, максимум 7. Результат расчёта виден до подтверждения.

После срока невыполненная неделя помечается **«Просрочено»**. Её можно отметить прочитанной без открытия администратором: сохранится дата отметки и статус **«С опозданием»**. Это дата внесения подтверждения на сервере. Прежние записи и недельные планы всё ещё нельзя менять, пока администратор не откроет неделю. Будущую неделю завершить нельзя. Книги на момент подтверждения сохраняются в снимке результата.

На телефоне доступны большие кнопки, быстрый выбор дней и карточки недель. В Excel добавлены книги, статус, дата отметки, просрочка и фактический темп; отдельный лист содержит план чтения на 22 недели.

При использовании GitDeck нажмите **«Обновить из Git» у марафона**. Панель и Пульс для этого обновлять не требуется. Затем перезагрузите страницу марафона.

Используйте **dist/reading-marathon-update.tar.gz**. Архив содержит код и ресурсы, не содержит `.env`, рабочую базу, compose-файлы или настройки Caddy. Токен бота и домены сохраняются.

С компьютера:

```powershell
scp C:/laragon/www/my_project/marathon/dist/reading-marathon-update.tar.gz root@2.28.57.159:/root/
```

На сервере для сайта с HTTPS и Telegram:

```bash
cd /opt/marathon
docker compose -f compose.https.yaml exec -T web php /opt/marathon/backup.php /var/lib/marathon/before-v2.sqlite
docker compose -f compose.https.yaml cp web:/var/lib/marathon/before-v2.sqlite /root/marathon-before-v2.sqlite
docker compose -f compose.https.yaml --profile telegram stop web bot
tar -xzf /root/reading-marathon-update.tar.gz -C /opt/marathon
docker compose -f compose.https.yaml up -d --build --wait web
docker compose -f compose.https.yaml --profile telegram up -d --build --no-deps bot
```

Если `before-v2.sqlite` уже существует, используйте другое имя. Для HTTP уберите `-f compose.https.yaml`; для общего прокси замените его на `-f compose.shared.yaml`. Если у вас нет бота, уберите `--profile telegram`. Не используйте `down -v`.

## Что произойдёт с данными

- Аккаунты, Telegram-привязки, пароли и старые отчёты сохраняются.
- Миграция добавляет новые таблицы и поля, не удаляет старые данные.
- Старые страницы/минуты остаются в блоке истории участника; их нельзя достоверно перевести в главы.
- Для новых недель создаётся план по **7 глав**. Сразу после обновления задайте фактические планы в «Настройки → План по 22 неделям».
- Уже прошедшие недели закрыты; администратор может открыть их для внесения фактических глав, затем снова закрыть.

## Новый порядок работы

1. Администратор задаёт число глав на каждую неделю.
2. Участник нажимает «Что я прочитал», выбирает дату, глав и название книги/глав.
3. Можно также написать привязанному боту **прочитал 50**. Отметка создаётся за текущий день и текущую неделю.
4. Сумма глав из ежедневных отметок, Telegram и ручного итога не может превысить план недели. Превышение отклоняется полностью; бот сообщает доступный остаток.
5. Один день с несколькими отметками считается одним днём чтения. В ручном недельном итоге можно задать дни отдельно или оставить автоматический подсчёт.
6. Дневной темп = округлённое вверх число оставшихся глав / оставшиеся календарные дни до воскресенья, включая сегодняшний день.
7. Админы и модераторы используют недельную ведомость: «Внести» или «✓ План». Закрытую неделю изменить нельзя; её открывает администратор.
8. «Excel .xlsx» экспортирует выбранную неделю и сводку за 22 недели. Это выгрузка; редактирование скачанного Excel не изменяет сайт.
9. Для существующего участника используйте «✎ Роль» или «Аккаунт и роль». Можно назначить модератора/администратора с привязанным Telegram, либо задать логин и пароль.

Проверьте после обновления: вход, участника с прежними отчётами, планы недель, одну новую отметку, Excel-экспорт и логи бота. Реальные Telegram-запросы проверяются на вашем сервере с вашим токеном; автоматические проверки проекта используют имитацию входящих updates.
