# Kirkom Cargo

Управление посылками и клиентами, статусы доставки, расчёт по весу,
частичные оплаты, финансовый журнал, уведомления WhatsApp и экспорт.
Node.js 24, SQLite в постоянном томе, без npm-зависимостей.

## GitDeck

Обновите GitDeck, затем карточку Kirkom Cargo через «Обновить из Git».
Первая установка или переход со старой версии создаёт контейнер приложения,
постоянный том и HTTPS-маршрут kirkom.vano.sbena.net.
Первоначальный пароль совпадает с паролем GitDeck на момент установки.
Пароли хранятся как scrypt-хеши. Серверные сессии действуют 12 часов.
Старые стандартные Nginx Dockerfile/Compose копируются в .before-cargo-server
при переходе на серверную версию. Пользовательские конфигурации не мигрируются.
Тариф требуется подтвердить в настройках перед первой приёмкой.
Старые данные localStorage не импортируются автоматически.

## Данные

Тариф и курс фиксируются в накладной; новые настройки не меняют прежние суммы.
Вес нельзя изменить после оплаты. Выдача доступна после полного расчёта.
Изменения используют версию состояния, конфликтующие записи отклоняются.
История операций сохраняется на сервере. «Выгрузить копию» экспортирует JSON.
Перед обновлением сделайте резервную копию постоянного Docker-тома cargo-data;
общий Docker-модуль GitDeck автоматически сохраняет только исходный код.
Восстановление выполняется администратором при остановленном контейнере.

## Подключения

WhatsApp: готовится текст, открывается личный чат по номеру; сообщение
отправляет оператор. Массовые и автоматические рассылки пока не реализованы.
Pinduoduo: прямой API не подключён, трек-номер вводит оператор.
В интерфейсе нет фиктивных статусов интеграций и отправки.
Доступ единой команды, один пароль оператора; персональные роли и аккаунты
пока не реализованы. Внешний доступ ограничьте сотрудниками через HTTPS.

## Личный кабинет клиента

Адрес `/client`. В панели: Клиенты → Доступ → скопировать приглашение.
Ссылка действует 7 дней и используется один раз. Клиент задаёт собственный пароль
(10–128 символов), затем входит по коду KC-… и паролю. Повторное приглашение
восстанавливает доступ; после смены пароля прежние клиентские сеансы отзываются.
Клиент видит только свои посылки, историю статусов и платежи. Чужие ID возвращают 404.
Сотрудники и клиенты используют разные серверные сессии и отдельные cookie.
Клиентские пароли хранятся как scrypt-хеши; ссылки — как SHA-256-хеши.

PWA-манифест позволяет установить кабинет на телефон через браузер.
На iPhone: Поделиться → На экран «Домой». На поддерживаемом Android кнопка
установки появляется в профиле. Данные и API не кешируются для офлайн-доступа.
Изменение статуса оператором видно после обновления кабинета. Онлайн-оплата
и вход по WhatsApp/SMS-коду не подключены. Первая версия истории старых посылок
показывает только известный статус, новые переходы записываются автоматически.

## Рабочие интеграции

Настройки → WhatsApp Business: Phone Number ID, WABA ID, токен системного
пользователя с whatsapp_business_messaging и whatsapp_business_management,
App Secret, версия Graph API, имя и язык одобренного текстового шаблона.
Пять позиционных параметров тела: имя клиента, трек, статус, вес, остаток в сомах.
Пример: «Здравствуйте, {{1}}! Посылка {{2}}: {{3}}. Вес {{4}} кг. К оплате {{5}} сом».
Динамические заголовки и кнопки этой версии не поддерживаются.
Сначала сохранить, затем проверить. Проверка читает номер и одобренные шаблоны
через официальный API; это не имитация подключения. Список ограничен первыми 100 шаблонами.

Callback URL: https://kirkom.vano.sbena.net/api/webhooks/whatsapp . Verify token
показывается сотруднику после сохранения. В Meta подписать поле messages.
POST проверяется по HMAC-SHA256 от исходных байтов с App Secret, неверные подписи
отклоняются. Статусы sent/delivered/read/failed приходят из Webhook, а не генерируются.
Входящее сообщение СТОП/STOP/Отписаться отзывает согласие по номеру телефона.
Входящие тексты хранятся 30 дней. Автоматические отправки изначально выключены.
После проверки можно включить уведомления об изменении статуса; без согласия
клиента они не отправляются. Отдельная кнопка отправки есть в карточке уведомления.

Очередь сохраняется в SQLite. Повтор одного requestId не создаёт новую отправку.
При тайм-ауте или 5xx нет автоматического повтора: статус «Нет подтверждения»,
чтобы не создавать дубликаты. После перезапуска sending также требует проверки
в Meta. Для нового осознанного отправления оператор заново открывает уведомление.
Журнал отображает ошибки провайдера без токенов; браузеру секреты не возвращаются.

Настройки → Pinduoduo: Client ID, Client Secret, Access Token авторизованного
аккаунта продавца. Метод pdd.order.information.get вызывается по HTTPS, параметры
подписываются MD5 в установленном протоколом Pinduoduo формате. Номер заказа
вводится оператором. Проверка доступа происходит при фактическом запросе заказа.
Сохраняются только номер заказа, трек, название товаров и статус, без адресов
и телефонов покупателя. Повторная загрузка обновляет одну запись. «Принять»
создаёт посылку с выбранным клиентом и измеренным весом по текущему тарифу.
Нет трека — приёмка недоступна. Чужие покупки клиентов и произвольные аккаунты
покупателей API продавца не открывает. OAuth-регистрация приложения и разрешения
оформляются в Pinduoduo отдельно; приложение не обходит ограничения платформы.

Ключи шифруются AES-256-GCM; мастер-ключ /data/integrations.key имеет права 0600.
Для восстановления копируйте весь Docker-том, включая мастер-ключ и password.json.
Один экспорт JSON или только SQLite не содержит полного комплекта для восстановления
секретов. Потеря мастер-ключа означает повторный ввод ключей интеграций.

Документация:
- https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/overview
- https://developers.facebook.com/docs/graph-api/webhooks/getting-started
- https://developers.facebook.com/documentation/business-messaging/whatsapp/messages/send-messages
- https://open.pinduoduo.com/application/document/api?id=pdd.order.information.get

Проверки интеграций выполняются с подменой сетевого транспорта: payload, шифрование,
подписи, отказ при неверном HMAC, дубликаты, статусы, отзыв согласия и неизвестный
результат отправки. Реальные аккаунты требуют введённых пользователем ключей;
без ключей подтверждение сквозной отправки и импорта невозможно.
