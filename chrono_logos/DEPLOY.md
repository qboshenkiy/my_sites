# Chrono Logos: установка через GitDeck

Проект использует PHP 8.3, CodeIgniter 4, PostgreSQL 17 и Apache с корнем `public/`.
Docker собирает зависимости строго из `composer.lock`; dev-зависимости не устанавливаются.

## Через панель

1. Обновите GitDeck до 1.2.2 или новее кнопкой «Обновить панель».
2. «Добавить модуль» → **Chrono Logos — игры**. Репозиторий `https://github.com/qboshenkiy/my_sites.git`, ветка `main`, папка в Git `chrono_logos`, каталог `/opt/chrono-logos`. Сохраните.
3. Нажмите «Обновить из Git». Для первой установки нужен пустой каталог. Панель создаст `.env`, Compose-конфигурацию и случайные пароли, затем соберёт приложение и выполнит миграции.
4. Откройте «Настройки сайта». Задайте `APP_URL=http://IP_СЕРВЕРА:8082/`, `ADMIN_USERNAME=admin`, свой `ADMIN_PASSWORD` от 12 символов. Сохраните и дождитесь завершения.
5. Откройте `APP_URL`, войдите с заданными логином и паролем. Начальные случайные пароли не раскрываются через браузер; свой пароль задаётся заменой поля.

Порт по умолчанию **8082**, отдельно от Пульса и марафона. Для доступа по IP разрешите его в сетевом экране сервера. PostgreSQL наружу не публикуется.

`ADMIN_USERNAME` и `ADMIN_PASSWORD` задают управляемый панелью аккаунт: при запуске ему выдаются права администратора и применяется указанный пароль. При смене имени прежний пользователь сохраняется. Самостоятельная регистрация в production даёт обычную роль; администратор создаётся до открытия HTTP.

## Домен

### Текущий сервер: тот же домен, порт 8083

1. Обновите **GitDeck** до **1.3.0**, затем обновите **Chrono Logos** из `main`.
2. Откройте **Chrono Logos → Настройки сайта**. Выберите общий HTTPS-прокси марафона
   (модуль должен использовать `compose.https.yaml`) и нажмите **Подготовить HTTPS на порту 8083**.
3. Проверьте `APP_URL=https://vano.sbena.net:8083/` и выбранный `HTTPS_PROXY_PROJECT`.
   Нажмите **Сохранить и применить**.
4. В Hetzner разрешите входящий **TCP 8083**. Порты 80/443 уже обслуживаются марафоном.
5. Откройте `https://vano.sbena.net:8083/`. Прежний HTTP-адрес с портом 8083 больше не используется.

Панель подключает web игры к сети существующего Caddy, убирает внешний HTTP-порт web,
добавляет TLS-слушатель 8083 и маршрут бота на основном порту 443. База и тома сохраняются.
Маршруты марафона сохраняются, новый домен/сертификат покупать не нужно. При применении
прокси кратковременно пересоздаётся. При ошибке панель возвращает прежние файлы и `.env`.

Серверные файлы `compose.gitdeck-https.yaml` создаются в обоих модулях, а в Caddyfile
добавляются блоки с маркерами GitDeck. Все следующие операции через панель учитывают
эти файлы. Не удаляйте их и не меняйте выбранный модуль прокси после подключения.
Если запускаете Compose вручную, добавляйте `-f compose.gitdeck-https.yaml`;
для Chrono Logos также `-f ops/compose.runtime.yaml`.

Для другой инфраструктуры по-прежнему можно подключить существующий прокси вручную:
задайте `APP_URL=https://ваш-домен/`, настройте маршрут и используйте `APP_BIND=127.0.0.1`
при прокси на хосте. Поле `HTTPS_PROXY_PROJECT` тогда оставьте пустым.

## Отдельный Telegram-бот и Mini App

1. Создайте **нового бота** через @BotFather. Токен бота марафона здесь не используется.
2. В GitDeck → Chrono Logos → Настройки сайта задайте `TELEGRAM_BOT_TOKEN` и
   `TELEGRAM_BOT_USERNAME` без `@`, сохраните и примените.
3. На сайте войдите администратором → **Профиль → Подключить игрового бота**.
   Кнопка настраивает меню **Играть**, команды `/start`, `/app` и webhook.
4. Отправьте новому боту `/start`. Игра откроется кнопкой внутри Telegram.

Прямой адрес Mini App — `https://vano.sbena.net:8083/telegram/app`.
Без запуска из Telegram доступен обычный сайт с входом по логину.
Новый игрок явно подтверждает создание профиля; Telegram не выдаёт ему права администратора.
Чтобы использовать существующий профиль, выберите **У меня уже есть аккаунт**,
войдите и нажмите **Профиль → Привязать Telegram** внутри Mini App.
Там же доступна отвязка. Для Telegram-профиля сначала задаётся первый пароль:
он позволяет входить в тот же профиль в Android и защищает от потери доступа при отвязке.

Для webhook используется отдельный маршрут на порту **443** общего прокси, потому что
[Telegram поддерживает ограниченный набор портов webhook](https://core.telegram.org/bots/api#setwebhook).
Сам Mini App работает на 8083. Подпись initData проверяется сервером, срок подтверждения —
один час; роль берётся из базы. Webhook проверяет секретный заголовок. CSRF отключён
только для точного маршрута webhook; вход, привязка и настройка бота защищены CSRF.
Подписанные данные и токен не сохраняются в localStorage или клиентских логах.

## Android

Отдельный APK открывает HTTPS-игру на порту 8083 и устанавливается рядом с марафоном.
Сборка через GitHub Actions или локально: [native/android/README.md](native/android/README.md).
Сначала подключите HTTPS по шагам выше, иначе APK не сможет открыть сервер.

## Данные и обновления

В отдельных именованных томах хранятся PostgreSQL, `writable/` (включая сессии) и `public/uploads/`. При обновлении эти каталоги не заменяются. Локальная `.env`, локальная база и картинки из рабочей копии на сервер автоматически не переносятся. При необходимости перенос существующих данных делается отдельно через дамп PostgreSQL и архив uploads.

Перед каждым последующим обновлением GitDeck останавливает web и сохраняет код и дамп PostgreSQL в закрытом каталоге задания. При неудаче восстанавливает предыдущий код и полную базу, включая схему. Выбор старого коммита в панели меняет версию кода; это не восстановление базы на прошлую дату.

Реквизиты уже созданной базы `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` через форму менять нельзя: переменные не переименовывают существующую базу и не меняют пароль роли PostgreSQL.

После сбоя первой установки код, `.env` и тома сохраняются: исправьте причину по журналу и повторите обновление. Не используйте `docker compose down -v`: эта команда удалит постоянные данные.

## Без панели

Из корня проекта на Linux с Docker Compose:

```sh
cp .env.example .env
# Укажите APP_URL, DB_PASSWORD и ADMIN_PASSWORD в .env.
cp ops/compose.yaml compose.yaml
docker compose up -d --build --wait --wait-timeout 180
```

Для проверки запуска: `docker compose ps`, `docker compose logs --tail=80 web`.

## Проверки

`tests/deploy_smoke.py` запускает отдельный временный PostgreSQL и копию приложения без локальной `.env`, проверяет чистые/повторные миграции, учётную запись администратора, HTTP-каталог и вход. Требует PHP с pgsql/intl и PostgreSQL binaries; пути задаются `PHP_BIN` и `PG_BIN`. Рабочая база приложения не используется.
