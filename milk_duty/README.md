# Молоко — личные напоминания о дежурстве

Отдельное приложение: веб-панель организатора, личный Telegram-бот, SQLite и постоянный Docker-том.
Python 3.11+ без внешних Python-пакетов. Панель и обработчик очереди работают одним процессом.

По умолчанию: общая очередь «дежурство + молоко», понедельник–пятница, 08:00 Asia/Bishkek.
Напоминание накануне включено на 19:00; время, тексты, дни, дата начала и отключение меняются на сайте.
О понедельнике напоминаем в воскресенье, а не в пятницу. Отправки изначально на паузе.

## Установка на существующий сервер

В SSH-консоли сервера, где уже есть Docker Compose V2 и GitDeck:

```bash
git clone --depth 1 https://github.com/qboshenkiy/my_sites.git /root/milk-duty-source
bash /root/milk-duty-source/milk_duty/install.sh
```

Если каталог исходников уже существует, сначала обновите его через `git -C /root/milk-duty-source pull --ff-only`.
Установщик копирует только новый проект в `/opt/milk-duty`, запускает его и просит задать пароль панели.
Повторная установка сохраняет Docker-том, токен бота, участников и историю; пароль задаётся заново.
Не выполняйте повторную установку во время обновления этого модуля через GitDeck.

На своём ПК откройте SSH-туннель:

```bash
ssh -N -o ExitOnForwardFailure=yes -L 8130:127.0.0.1:8130 root@2.28.57.159
```

Панель: <http://localhost:8130>. Можно выбрать другой локальный порт, если 8130 занят.

### HTTPS: milk.vano.sbena.net

Создайте DNS-запись A `milk.vano.sbena.net` → IP сервера (2.28.57.159).
При наличии wildcard-записи это может уже работать. В SSH-консоли:

```bash
cd /opt/milk-duty
python3 src/connect_https.py milk.vano.sbena.net
```

Скрипт использует существующий Caddy из модуля Marathon в GitDeck (или Pulse), добавляет
только отдельный маршрут и Docker-сеть нового приложения. Другие сайты не пересоздаются.
Есть валидация Caddy и возврат файлов при ошибке. При нескольких прокси можно выбрать `--proxy ID`.
Если старый основной маршрут использует неоднозначный `web:80`, скрипт откажется менять сеть;
сначала исправьте стабильный alias через GitDeck. До этого используйте SSH-туннель.
Получение сертификата требует правильного DNS и доступных портов 80/443.

### Подключить обновления в GitDeck

Добавить модуль → **другой Docker-проект**:

| Поле | Значение |
|---|---|
| ID | `milk-duty` |
| Название | `Молоко — дежурства` |
| Репозиторий | `https://github.com/qboshenkiy/my_sites.git` |
| Ветка | `main` |
| Папка внутри Git | `milk_duty` |
| Каталог сервера | `/opt/milk-duty` |
| Compose | `compose.yaml` |
| Основной сервис / сервисы | `web` |
| Профили | пусто |
| Пути к коду | `src`, `web` |
| Проверка health | включена |

Dockerfile, Compose и том создаются первой установкой. GitDeck обновляет только `src` и `web`;
существующий `compose.gitdeck-https.yaml` он подхватывает автоматически. База и настройки в томе остаются.
У сторонних Docker-модулей GitDeck резервирует только код: резервную копию SQLite делайте отдельно.

## Всё остальное — через сайт

1. В настройках подключите токен **нового отдельного** бота из @BotFather. Токен не нужен в чате с Codex.
   Бот должен работать без webhook и без второго запущенного polling-процесса.
2. Добавьте участников по именам в порядке очереди. Откройте карточку каждого и скопируйте его личную ссылку.
3. Отправьте ссылки участникам самостоятельно. Каждый открывает свою ссылку и нажимает «Старт».
   Ссылка действует 7 дней и используется один раз. Новый токен ссылки можно выпустить в карточке.
4. В настройках выберите дату начала и включите личные напоминания. Неподключённые участники не входят в очередь.
5. При необходимости отправьте тестовое сообщение выбранному подключённому человеку из настроек.

В панели: порядок очереди стрелками, переименование, пауза участника, календарь на три недели,
замена на выбранную дату, сообщения, часовой пояс, смена пароля и история доставки.
Замена не сдвигает обычную очередь. После уже отправленного напоминания обоим участникам
поступает уточнение: прежнему — отмена, новому — назначение (при включённых отправках).

Утреннее напоминание привязано к конкретному дежурству и сохраняется в SQLite.
При перезапуске в тот же день пропущенное утреннее сообщение догоняется до полуночи.
Накануне — от выбранного времени до утреннего напоминания. После окончания окна сообщения истекают.
Повторный опрос не создаёт повторных заданий. Ошибки сети повторяются с задержкой;
блокировка бота участником отображается как ошибка, а не как успешная доставка.
Telegram не предоставляет ключ идемпотентности sendMessage: при потере ответа после доставки
или аварии между отправкой и фиксацией результата возможен повтор сообщения.

Очередь считается от даты начала по текущим активным подключённым участникам. Просмотр не закрепляет даты.
После первого напоминания назначение закрепляется (метка «Закреплено»), ручная замена — тоже.
Изменение состава/порядка меняет ещё не закреплённые будущие даты. Перед паузой человека,
у которого есть закреплённые дежурства сегодня или в будущем, сначала назначьте замены.
Если день недели выключен или дата начала перенесена позже, сообщения за исключённые даты не отправляются.
Для полного сброса очереди без переноса дат отдельной кнопки пока нет.

Пароль панели хранится как scrypt-хеш; сессии с CSRF, HttpOnly-cookie и проверкой Origin.
Токен хранится только в приватной SQLite-базе на сервере, не возвращается в API состояния и не логируется.
Файл базы и резервные копии содержат токен и Telegram ID, поэтому они должны оставаться приватными.
При восстановлении/обновлении APK других проектов этот бот никак не затрагивается.

## Резервная копия и пароль

```bash
cd /opt/milk-duty
docker compose exec -T web python src/backup.py /data/backup.sqlite
docker compose cp web:/data/backup.sqlite /root/milk-duty-backup.sqlite
chmod 600 /root/milk-duty-backup.sqlite
```

Забытый пароль можно сбросить, не удаляя базу:

```bash
docker compose exec web python src/app.py password
```

После подключения HTTPS используйте при ручных `up` также оверлей:
`docker compose -f compose.yaml -f compose.gitdeck-https.yaml up -d --build --wait`.
Не удаляйте том `duty-data` при обновлении.

## Локальная разработка

```bash
python3 src/app.py password
python3 src/app.py serve
```

Панель <http://127.0.0.1:8130>. `DATA_DIR` задаёт каталог приватных данных;
`TRUST_PROXY=1` разрешает доверять `X-Forwarded-Proto` только за доверенным прокси.
По умолчанию Python слушает loopback, Docker-порт тоже опубликован только на loopback.

Проверки из корня общего репозитория:

```bash
python3 -m unittest discover -s milk_duty/tests -v
node --check milk_duty/web/app.js
bash -n milk_duty/install.sh
```
